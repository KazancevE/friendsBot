# BRO — демо бота мужской парикмахерской

Демо записи и бонусной карты для сети **BRO** (Барнаул, четыре филиала) на базе friendsBot. Черновой PR в `main`, **не мержить**: это демо, не замена кальянной «Друзья».

Данные салона — `src/venue/salon.ts`. Следующее демо собирается правкой этого файла, лендинга `site/index.html` и цветов в CSS, без перестройки записи.

Один процесс, одна база Postgres. Два мессенджера — Telegram (grammY) и MAX (официальный `@maxhub/max-bot-api`, запросы на `platform-api2.max.ru`). Клиент склеивается по телефону: карта, баланс и записи общие.

Игры, квиз, схема зала и бронь столов в гостевом интерфейсе этого форка выключены. Доменный код кальянной остаётся в репозитории, чтобы старые тесты не разъехались.

## Что умеет демо

- Запись: филиал → услуга → мастер или «любой» → день → свободное окно → подтверждение. Окна считаются из длительности услуги и уже занятого времени.
- То же в чате и в Mini App.
- Напоминания за 24 часа и за 2 часа, кнопка отмены.
- «Пора стричься» через N недель после визита (по умолчанию 4) — только если клиент согласился на рекламные сообщения.
- Знакомство по «Старт» в Telegram и при запуске бота в MAX: приветствие, согласие на персональные данные, отдельное согласие на рассылку, телефон, имя, день рождения по желанию. Ссылка `?start=ref_…` сохраняется до конца.
- Кэшбэк (сид ставит 5%), реферал, бонус на день рождения, QR на кассе.
- Баланс общий. Визит в админке помечается филиалом.
- Сайт с ценами и адресами, админка на `/admin`.

Часовой пояс по умолчанию **Asia/Barnaul** (UTC+7), не Москва. Меняется `VENUE_TIMEZONE` и полем в настройках админки.

Телефоны салона в сид и рассылки **не** попадают. Никому ничего не отправляется, пока вы сами не впишете токены.

## Локальный запуск

Нужны Docker и свободный порт 3000.

```sh
cp .env.example .env
docker compose up -d --build
```

Откроется:

| Адрес | Что это |
|---|---|
| http://localhost:3000/ | лендинг, прайс, мастера, кнопки «Записаться» |
| http://localhost:3000/admin/ | админка. Логин `admin`, пароль `bro-demo` |
| http://localhost:3000/site/chat.html | диалог `/start` без живого Telegram |
| http://localhost:3000/app/?demo=1 | карта гостя и запись без мессенджера |

При старте контейнер сам накатывает миграции и сид из `src/venue/salon.ts`: четыре филиала, карточки мастеров по уровню, прайс, пример акции «−20% на первый визит», демо-гость «Демо Гость» и две будущие записи. Повторный сид не затирает уже сохранённые цены и процент кэшбэка.

Без токенов боты не поднимаются, сайт работает. Логи: `docker compose logs -f app`.

Остановка: `docker compose down`. База остаётся в томе `pgdata`.

Только Postgres на localhost (для `npm run start`):

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres
```

В `DATABASE_URL` для npm замените хост `postgres` на `localhost`.

Проверки:

```sh
npm test
npm run build
curl -s http://localhost:3000/health
```

## Токены

### Telegram

1. @BotFather → `/newbot` → скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. Username бота без `@` — в `TELEGRAM_BOT_USERNAME` (кнопка на сайте и реферальная ссылка).
3. `TELEGRAM_ADMIN_ID` — Telegram id администраторов через запятую. По умолчанию `500459806`: новые и отменённые записи приходят этому чату, команда `/admin` открывает ссылку на веб-админку. Другой id или несколько id задаются в `.env`, в коде список не зашит.
4. Mini App: в BotFather укажите `https://ваш-домен/app/`. Локально без HTTPS бот ходит long polling, webhook не ставится.
5. На HTTPS (`PUBLIC_URL` начинается с `https://`) процесс сам вызывает `setWebhook` на `/tg/webhook`. Если Telegram не открывает входящее соединение до VPS, поставьте `TELEGRAM_TRANSPORT=polling`: бот забирает апдейты сам, кнопка «Карта» всё равно ведёт на `PUBLIC_URL`.
6. Если с сервера не открывается `api.telegram.org`, укажите `TELEGRAM_PROXY` (`socks5h://` или `http://`). Через него идут и polling, и отправка сообщений.
7. Кнопка «Карта» должна принадлежать боту с тем же `TELEGRAM_BOT_TOKEN`. Mini App проверяет `initData` и показывает карту, только если знакомство в чате закончено. Иначе на экране написано, что вернуться в чат и нажать «Старт». В полноэкранном режиме шапка учитывает `safeAreaInset` и `contentSafeAreaInset`, чтобы логотип не заезжал под кнопки Telegram. У MAX тот же вход через `initData` и отступ `env(safe-area-inset-*)`, отдельных insets у моста MAX нет.

### MAX

Официальная схема: [dev.max.ru](https://dev.max.ru/docs-api), библиотека `@maxhub/max-bot-api`.

1. Создайте бота в MAX для бизнеса или через @MasterBot и скопируйте токен в `MAX_BOT_TOKEN`.
2. Ссылка на бота — `MAX_BOT_URL` (например `https://max.ru/имя`).
3. Свой числовой id в MAX — `MAX_ADMIN_USER_ID`, если нужны уведомления в MAX.
4. Демо использует long polling (`bot.start()`), хост API `platform-api2.max.ru`. С июня 2026 сертификат Минцифры: в обычном Node его нет в доверенных. Если polling падает с ошибкой TLS, добавьте корневой сертификат НУЦ Минцифры в систему или в `NODE_EXTRA_CA_CERTS`.
5. Webhook MAX (`POST /subscriptions`) в этом демо не включён: один контейнер и polling проще. Для нескольких реплик переведите MAX на webhook, иначе обновления заберёт только один процесс.

## Импорт базы

Раздел **Импорт** в `/admin` принимает CSV или Excel из текущей системы записи и сам предлагает соответствие столбцов. Жёсткого набора колонок нет: имя, телефон, день рождения, комментарий, последний визит, число визитов, сумма, будущая запись. Образец с явно выдуманными людьми — `fixtures/dikidi-clients-sample.csv` (телефоны вида 900 000-00-xx, пометки «ФИКТИВНЫЙ»). Его же можно скачать из админки.

Что делает импорт:

- телефон приводится к `+7`, дубли в файле и уже существующие карты сливаются по номеру;
- перед записью — предпросмотр с ошибками и предупреждениями, потом отчёт;
- повтор того же файла не создаёт вторую карту, второй визит и вторую запись;
- импортированный клиент без Telegram и MAX. Когда он сам откроет бота и пришлёт телефон, карта и история (визиты, записи) остаются на этой карте;
- дата последнего визита кормит «пора стричься», день рождения — бонус ко дню рождения;
- приветственный бонус при первой привязке к мессенджеру выключен (0 ₽) и включается в «Настройках»;
- при импорте никому ничего не пишется.

## Допущения демо BRO

- Длительности услуг в открытом прайсе нет. В `src/venue/salon.ts` стоят оценочные: обычные 30–60 минут, комплексы и «Отец + сын» дольше. На сайте они помечены «примерно», в админке длительность можно сменить.
- На Лазурной нет «Королевского бритья» и «Стрижки + Королевское бритьё» — так в выгрузке Яндекса. Это не подтверждено как отказ филиала, в демо этих двух услуг там нет.
- Имён и фото мастеров в открытых источниках нет. В каждом филиале 2–3 карточки уровней «Мастер», «Топ-мастер», «Амбассадор», без фотографий людей и без отдельных цен по уровню.
- Бонус на день рождения в источниках не назван суммой. В демо 500 ₽, меняется в «Настройках». Кэшбэк 5%, реферал 300/300 и «пора стричься» через 4 недели — как в задании на демо.
- Акция «−20% на первый визит» только карточка в админке, раздел «Акции». К записи и чеку она не применяется.
- Юридическое лицо и ИНН в открытых источниках не найдены. В политике их нужно вписать в `.env`, когда появятся.

## Новый салон за вечер

1. **Конфиг салона.** Филиалы, прайс, мастера, тексты бота, бонусы и пример акции — `src/venue/salon.ts`. Сид читает его сам.
2. **Окружение.** Скопируйте `.env.example`. Токены, `PUBLIC_URL`, `VENUE_TIMEZONE`, логин админки. Пароль `bro-demo` смените.
3. **Бренд.** Тексты лендинга — `site/index.html`. Чёрный фон, белый текст, акцент `#F0B820` — `site/styles.css`, `admin/src/salon.css`, `miniapp/src/salon.css`. Логотип — `site/logo.png`.
4. **Процент и «пора стричься».** Первый сид пишет 5% и 4 недели. Дальше — экран «Настройки», ключ `salon.seeded` не даёт сиду затереть правки при рестарте.
5. **Запуск.** `docker compose up -d --build`. Для боевого HTTPS: `docker compose --profile https up -d` и домен в `CADDY_DOMAIN` / `PUBLIC_URL`.
6. **Проверка.** Запись с сайта (`/app/?demo=1`), та же запись в чате бота, отмена, чек в админке на клиента, QR на карте.

Кассу проводит пользователь «Касса» из сида (роль admin). Сторонней CRM нет: клиенты, баллы и рассылки живут в этой Postgres.

## Продакшн

Боевой вариант рассчитан на сервер разработчика: Ubuntu, Docker, один салон на каталог. Несколько салонов на одной машине — отдельные каталоги, см. ниже. Файл `docker-compose.prod.yml` сам занимает порты 80 и 443 (Caddy, сертификат Let's Encrypt по `CADDY_DOMAIN`). Если на этой машине 80/443 уже отдаёт другой nginx, этот compose не поднимать, пока сайт не перенесён: иначе чужие сайты останутся без порта.

Локальный `docker compose up` и демо-пароль `bro-demo` для боя не подходят. В образе `NODE_ENV` всегда `production`, поэтому боевой режим включается отдельно: `APP_ENV=production`. С ним процесс не стартует, если пароль администратора короткий или демо (`bro-demo`, `daddyson-demo`), секрет сессии короткий или из примера, пароль Postgres пустой или демо (`bro`, `daddyson`), нет `DEV_ALERT_CHAT_ID`, юридического имени, ИНН (10 или 12 цифр), домена и `https://` в `PUBLIC_URL`, либо включён демо-гость. Пустой `TELEGRAM_BOT_TOKEN` старт не блокирует: сайт, админка и карта открываются, бот и тревоги молчат, пока токен не появится.

### Первый запуск

На чистой Ubuntu из каталога проекта, от root, после заполнения `.env`:

```sh
cp .env.example .env
# пароли, TELEGRAM_BOT_TOKEN, PUBLIC_URL=https://домен, CADDY_DOMAIN,
# TELEGRAM_ADMIN_ID и DEV_ALERT_CHAT_ID уже 500459806, смените при другом владельце
# OPERATOR_LEGAL_NAME, OPERATOR_INN, OPERATOR_ADDRESS
chmod +x scripts/bootstrap-ubuntu.sh scripts/update.sh scripts/restore.sh
./scripts/bootstrap-ubuntu.sh
```

Скрипт ставит Docker, если его нет, открывает в ufw SSH, 80 и 443 и поднимает compose. Миграции и сид выполняет контейнер `app` при старте. Проверка: `curl -fsS https://домен/health/ready` → `{"ok":true}`. Живой процесс отвечает и на `/health` (без базы).

Что входит в стек: Postgres без порта наружу, приложение без порта наружу, Caddy, контейнер копий и сторож. У всех `restart: unless-stopped`, лимиты CPU/памяти и json-логи Docker (10 МБ × 5 файлов). Приложение пишет строки JSON в stdout: время, уровень, сообщение.

### Обновление

Из каталога салона:

```sh
./scripts/update.sh
```

Сначала свежий дамп в контейнере `backup`, затем `git pull --ff-only`, пересборка и `prisma migrate deploy`.

### Копии и восстановление

Раз в сутки в часовом поясе салона (`BACKUP_HOUR`, по умолчанию 3:15) `pg_dump --format=custom` кладёт файл в том `backups`: `daily/daily-ГГГГ-ММ-ДД.dump`. В воскресенье по этому же поясу копия ещё и в `weekly/`. Хранятся 7 ежедневных и 4 еженедельных, старее удаляются. При старте контейнера копия снимается сразу, затем ждёт ближайшие 3:15.

Чтобы дублировать дамп вне сервера, заполните `BACKUP_S3_*`. Подойдёт любой S3-совместимый бакет, в том числе reg.ru и Yandex Object Storage. Пустой `BACKUP_S3_BUCKET` — только диск сервера. Это отдельные ключи, не `S3_*` для картинок меню.

Список и выгрузка на хост:

```sh
docker compose -f docker-compose.prod.yml exec backup ls /var/backups/bro/daily
docker compose -f docker-compose.prod.yml cp backup:/var/backups/bro/daily/daily-2026-09-29.dump ./restore.dump
./scripts/restore.sh ./restore.dump
```

`restore.sh` останавливает приложение и сторожа, базу не трогает контейнером, накатывает дамп через `pg_restore --clean` и снова запускает приложение. Предупреждения pg_restore (код 1) не считаются провалом. Скрипт читает `.env` как файл оболочки: значения с пробелами, например юридическое имя, берите в кавычки.

Статус последней копии: `status.json` в том же томе (`ok`, `at`, `error`).

### Тревоги

Сторож раз в минуту открывает `http://app:3000/health/ready` и читает `status.json`. В Telegram-чат `DEV_ALERT_CHAT_ID` уходит сообщение `BRO: …`, если сайт или база не отвечают, копия не удалась, статуса нет дольше двух часов после старта или дамп старше 26 часов. По умолчанию это `500459806`, в `.env` чат можно сменить. Без `TELEGRAM_BOT_TOKEN` сторож только пишет предупреждение в лог. Повтор той же причины — не чаще раза в 30 минут. Исходящие к Bot API идут через `TELEGRAM_PROXY`, если он задан. Сторож не ждёт, пока приложение станет healthy: иначе при падении процесса тревога не уйдёт.

### Админка

Несколько учёток в таблице `AdminAccount`. Роли:

- **owner** — вся сеть: цены, импорт, мастера, настройки, учётные записи, выгрузка и удаление данных клиента;
- **branch_admin** — один филиал: календарь, клиенты, чек, списание, рассылка, выгрузка и удаление данных только своих клиентов;
- **master** — тот же объём на чтение, без чека, рассылки и персональных операций. Смена своего пароля доступна всем ролям.

Пока в таблице нет ни одной учётки, вход идёт логином и паролем из `.env`, роль владельца. Первый боевой старт записывает этого владельца (пароль хранится как scrypt). Дальше пароль из `.env` для входа не используется: смена пароля и новые люди — экран «Доступ» и «Пароль». Нельзя удалить единственного владельца. Неудачный вход: 8 попыток с одного IP за 15 минут, затем ответ «подождите».

### Персональные данные

Знакомство начинается с `/start` в Telegram и с события запуска бота в MAX, а не внутри записи.

1. Приветствие и короткое объяснение.
2. Согласие на обработку персональных данных: ссылки на `/privacy` и `/consent`, кнопки «Согласен» и «Не согласен». Без согласия запись и карта недоступны.
3. Отдельное согласие на рекламные рассылки. Отказ не блокирует бота и не отключает сервисные сообщения: подтверждение записи, отмена, напоминания за 24 часа и за 2 часа. Не уходят акции и «Пора стричься».
4. Телефон кнопкой контакта. Если номер уже есть в импорте, карта привязывается.
5. Имя: подставляется из профиля, его можно оставить или написать другое.
6. День рождения можно пропустить. Если указать, в этот день начисляется бонус.
7. Меню и кнопка мини-приложения «Карта».

Для каждого согласия хранятся время и версия документа (`POLICY_VERSION`, по умолчанию `2026-09-29`). Новая версия при следующем `/start` или любом сообщении снова спрашивает оба согласия, телефон и имя не переспрашивает. Рассылка в админке берёт только тех, у кого согласие на рекламу дано для текущей версии. Глубокая ссылка `start=ref_…` не теряется по дороге.

Если человек открыл запись или мини-приложение, не закончив знакомство, бот и экран карты возвращают его в чат.

На сайте: `/privacy` и `/consent`. Имя, ИНН и адрес оператора берутся из `OPERATOR_LEGAL_NAME`, `OPERATOR_INN`, `OPERATOR_ADDRESS`. Ссылки есть в подвале лендинга.

По запросу клиента администратор в «Клиентах» скачивает JSON (профиль, оба согласия, записи, визиты, баллы) или нажимает «Удалить данные»: имя становится «Удалён», телефон, день рождения и согласия очищаются, визиты и проводки остаются.

### Несколько салонов на одном сервере

Каждый салон — свой каталог, свой `.env`, свой `docker compose -p имя`, свой токен бота, свой `DATABASE_URL` и свой домен. Общую базу и общий токен не делить.

Порты 80 и 443 может занять только один Caddy. Практичный вариант: у первого салона Caddy как в этом файле, остальные стеки без своего Caddy в общей сети Docker, а сайты дописываются блоками в один `Caddyfile` (`домен { reverse_proxy имя-app:3000 }`). Либо один внешний nginx на хосте и публикация приложений только на `127.0.0.1`.
